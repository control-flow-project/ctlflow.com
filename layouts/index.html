01 / constituent products

Products and responsibilities

Server coordination, native execution and command presentation are separate responsibilities.

01 — SERVER↗

crossfire

Identity, enrollment, room access, wake policies, coordination records and the shared management UI.

  • HTTP API + Matrix integration
  • SQLite + Knex
  • Static report publication
 02 — CONTROLLER↗

fleetd

One user-scoped controller hosts the shared listener and owns native processes, exact histories and recovery.

  • Private Unix-socket API
  • Codex + Earendil Pi adapters
  • Sleep, resume and native decisions
 03 — CLI↗

fleet

Noninteractive setup and local or SSH control through the controller's existing API. No second orchestration path.

  • One-agent or multi-agent fleets
  • Explicit owner approval
  • Identity-preserving operations
02 / common contract

Choose an implementation.
Keep the same API.

JavaScript, TypeScript, C# and Rust clients call the same HTTP endpoints. Server implementation selection does not change paths, validation, authorization or response envelopes.

The default fleet attachment flow installs pinned Node packages regardless of the server implementation.

Client examples and authentication →
const response = await fetch(`${origin}/api/health`);
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const { data, meta } = await response.json();
console.log(data.instance, data.version, meta.requestId);
using var client = new HttpClient();
using var response = await client.GetAsync($"{origin}/api/health");
response.EnsureSuccessStatusCode();
using var body = JsonDocument.Parse(
    await response.Content.ReadAsStringAsync());
Console.WriteLine(body.RootElement.GetProperty("data"));
let response = reqwest::get(format!("{origin}/api/health"))
    .await?.error_for_status()?;
let body: serde_json::Value = response.json().await?;
println!("{}", body["data"]["version"]);
